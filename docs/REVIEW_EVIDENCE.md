# 审查证据与恢复语义

更新：2026-09-26。

## 执行状态和审查结论

`completed` 表示任务流程执行结束。代码是否存在已登记缺陷、审查证据是否完整，由 `GET /api/runs/{run_id}/review-report` 单独返回：

| outcome | 含义 |
| --- | --- |
| `changes_requested` | 当前代码快照存在已登记的定位缺陷 |
| `no_findings` | 已读取完整可审查 diff 并交付总结，当前快照没有登记缺陷；不保证不存在漏报 |
| `incomplete` | 缺少当前版本的阅读证据、diff 被截断、有文件被排除、缺少总结，或验收结果与当前代码不匹配 |

普通对话及升级前任务的 `report` 为 `null`，不会把缺失证据包装成审查通过。报告保留 HEAD、工作区摘要、finding ID、覆盖缺口、验收回执及时间。页面独立显示审查结论与验收退出码，任务状态变化后重新读取最终证据。

阅读证据由 `review_local_diff` 工具执行时记录，仅在可信控制器的审查阶段生效。代码修改阶段调用同一工具不能充当独立复审证据。重新执行复审前清空旧阅读回执。所有证据写入和对应事件在同一数据库事务内提交，并验证任务租约令牌。

## 快照覆盖范围

相对准备阶段 baseline 检查已跟踪文件的最终内容，以及未被 Git ignore 排除的新文件。快照包含 HEAD、baseline、文件路径、模式和内容摘要；新增、修改、删除、重命名会使摘要变化。

`.env`、`.env.*`（示例文件除外）、密钥文件及敏感目录不进入模型 diff；被排除文件的内容仍参与指纹，不能沿用旧快照的人工确认。大文件、二进制、符号链接和无法稳定定位的特殊文件名列为覆盖缺口。diff 返回上限为 100,000 字符，截断后结论为 `incomplete`。

摘要不覆盖 Git ignore 排除的文件、容器镜像变化或外部依赖状态；它是工作区代码身份，不是完整构建环境证明。报告是历史快照记录，后续修改需新建审查。当前报告覆盖检查以工具阅读回执为依据，不证明模型理解了每一行，也不是阻止发布的自动质量门禁。

## 恢复时的阶段复用

1. 代码实现继续使用 LangGraph Checkpoint；已结束的图读取原回答，不再次调用实现模型。
2. 成功验收回执持久化到 `review_evidence`。只有同一任务、相同 HEAD/工作区摘要、相同命令且退出码为 0 才复用。
3. 验收命令若修改了纳入快照的文件，回执仍绑定执行前输入；新工作区不能据此获得完整审查结论。
4. 已完成且证据完整的独立复审，在快照与验收回执未变时复用；否则重新审查。

这不提供任意 shell 命令的 exactly-once 执行：命令完成但回执提交前崩溃，显式恢复可能再次执行。验收应使用可重复的本地检查命令。变更镜像、忽略文件或外部依赖后应新建修复/验收任务，不能依赖旧回执。
