# SQLite 数据库迁移技术方案

## 一、需求理解

当前项目 `ai_coding` 是一个基于 FastAPI 的 Web 应用，提供用户注册/登录/修改/删除、部门管理、Excel 上传等模块。所有数据持久化均使用 **JSON 文件**（`users.json`、`departments.json`、`data_*.json`）和**进程内存字典**（`SESSION_STORE`、`_query_history`）。

本次需求是将项目的数据存储层从 JSON 文件 **迁移为 SQLite 数据库**，提升数据一致性、查询便利性和并发安全。

### 当前存储方式一览

| 数据实体 | 当前存储 | 文件/变量 | CRUD 操作 |
|---------|---------|----------|----------|
| 用户 (users) | JSON 文件 | `users.json` | `_load_users()` / `_save_users()` 全程读写 |
| 部门 (departments) | JSON 文件 | `departments.json` | `_load_departments()` / `_save_departments()` 全程读写 |
| 会话验证码 (captcha) | 进程内存 | `SESSION_STORE: dict` | 增/删/查 |
| 上传数据 (upload) | JSON 文件 | `data_{filename}.json` | 写 + 预览 |
| 查询历史 (query_history) | 进程内存 | `_query_history: list[dict]` | 增/查（非持久化，最多 10 条） |

## 三、数据结构、接口或页面变化

### 3.1 数据库表设计（SQLite Schema）

```sql
-- 部门表
CREATE TABLE IF NOT EXISTS departments (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    name    TEXT    NOT NULL UNIQUE
);

-- 用户表
CREATE TABLE IF NOT EXISTS users (
    username      TEXT PRIMARY KEY,
    password      TEXT NOT NULL,
    department_id INTEGER,
    FOREIGN KEY (department_id) REFERENCES departments(id)
);

-- 验证码会话表（替代 SESSION_STORE 字典）
CREATE TABLE IF NOT EXISTS sessions (
    session_key  TEXT PRIMARY KEY,   -- e.g. "abc123:captcha"
    captcha_text TEXT NOT NULL,
    created_at   TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 查询历史表（替代 _query_history 列表）
CREATE TABLE IF NOT EXISTS query_history (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    username        TEXT NOT NULL,
    department_name TEXT NOT NULL,
    created_at      TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 上传记录表（替代 data_*.json 文件）
CREATE TABLE IF NOT EXISTS upload_files (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    filename   TEXT    NOT NULL,
    base_name   TEXT   NOT NULL,
    headers    TEXT    NOT NULL,  -- JSON 数组
    rows_count INTEGER NOT NULL DEFAULT 0,
    created_at TEXT    NOT NULL DEFAULT (datetime('now'))
);

-- 上传数据行表
CREATE TABLE IF NOT EXISTS upload_rows (
    id        INTEGER PRIMARY KEY AUTOINCREMENT,
    file_id   INTEGER NOT NULL,
    row_data  TEXT    NOT NULL,  -- JSON 对象
    FOREIGN KEY (file_id) REFERENCES upload_files(id) ON DELETE CASCADE
);
```

## 四、具体实施步骤

### 步骤 1：新增数据库初始化模块 (db.py)

新建 `db.py`，包含：
- `DATABASE = "app.db"` 常量
- `get_db()` — 创建/返回数据库连接（`sqlite3.connect`），启用 WAL 模式、外键约束
- `init_db()` — 执行 `CREATE TABLE IF NOT EXISTS` 建表语句 + 插入 3 个默认部门种子数据（技术部/产品部/运营部），使用 `INSERT OR IGNORE`

### 步骤 2：创建数据访问层 (dal.py)

新建 `dal.py`，将所有数据操作封装为函数：

```python
# 用户
dal.create_user(username, password, department_id=None)
dal.get_user(username) -> dict | None
dal.update_user_password(username, new_password)
dal.delete_user(username)
dal.list_users() -> list[dict]
dal.list_users_by_department(department_id) -> list[dict]

# 部门
dal.list_departments() -> list[dict]
dal.list_departments_with_member_count() -> list[dict]  # JOIN + GROUP BY
dal.add_department(name) -> int
dal.get_department_name(department_id) -> str

# 验证码
dal.set_captcha(session_key, captcha_text)
dal.get_captcha(session_key) -> str | None
dal.delete_captcha(session_key)

# 查询历史
dal.add_query_history(username, department_name)
dal.get_query_history(limit=10) -> list[dict]

# 上传
dal.save_upload(filename, base_name, headers, rows_data) -> int
```

所有函数内部使用 `get_db()` 获取连接，通过 `with` 或用 `try/finally` 确保连接归还。

### 步骤 3：重构 main.py

按以下顺序进行：

1. **文件顶部**：移除 `USERS_FILE`、`DEPARTMENTS_FILE` 常量，改为 `from db import init_db` 和 `from dal import ...`
2. **启动初始化**：用 FastAPI `@app.on_event("startup")` 替代 `_ensure_departments_file()` 的模块级调用，执行 `init_db()`
3. **逐模块替换**：将每个业务函数中对 JSON 文件 `_load_*`/`_save_*` 的调用替换为 `dal.*` 函数调用
4. **验证码模块**：`SESSION_STORE` 字典操作全部改为 `dal.set_captcha/get_captcha/delete_captcha`
5. **部门查询历史**：`_query_history` 列表 + `_add_query_history()` 改为 `dal.add_query_history/get_query_history`
6. **上传模块**：将 `data_{base_name}.json` 的写入替换为 `dal.save_upload()` 数据库写入

### 步骤 4：更新测试文件

测试文件中需要关注以下几点：

1. **Fixture 调整**：`setup_module()` / `teardown_module()` 中不再操作 `users.json`，改为在每个测试前后操作 SQLite 数据库（delete/insert 回滚或使用临时数据库）
2. **文件存在性断言**：如 `test_register.py` 中 `assert os.path.exists("users.json")` → 改为验证 `dal.get_user("newuser")` 不为 None
3. **上传模块清理**：不再清理 `data_*.json`，改为清理 `upload_files`/`upload_rows` 表
4. **会话存储测试**：`test_login.py` 中对 `SESSION_STORE` 的断言改为验证 `sessions` 表中的行

## 六、风险点和需要用户确认的事项

### 6.1 风险点

| 风险 | 等级 | 说明 | 缓解措施 |
|------|------|------|---------|
| **并发写入** | 🔴 高 | JSON 文件原本没有并发保护，SQLite 默认也是单写。但 `main.py` 每次读写都打开/关闭文件，迁移到 SQLite 后如果用 WAL 模式可以缓解 | 启用 WAL 模式、使用连接超时（`timeout=10`） |
| **日期时间依赖** | 🟡 中 | `sessions` 和 `query_history` 表的 `created_at` 默认用了 `datetime('now')` UTC 时间，可能与本地时间有差异 | 确认是否需要改用本地时间 `datetime('now','localtime')` |
| **旧 JSON 数据迁移** | 🟡 中 | 如果已有 `users.json` 和 `departments.json` 中有数据，需要一次性迁移到 SQLite | 编写迁移脚本 `migrate_json_to_sqlite.py`，或直接清空重新开始 |
| **SESSION_STORE 行为变化** | 🟢 低 | 原来是进程内存，重启丢失。SQLite 持久化后重启仍在，可能需要清理过期验证码 | 可选增加定时清理或 TTL 逻辑，但原项目没有，暂可不加 |
| **测试中硬编码的文件检查** | 🟢 低 | 测试直接检查 `users.json` 文件存在性，不再是有效断言 | 逐测试更新 |
| **上传功能变化** | 🟢 低 | 原来直接写 JSON 文件到工作目录，现在存入数据库 | 上传结果模板中不再显示 `saved_path` 字段，需调整 |

### 6.2 需要用户确认的事项

1. **数据库文件路径**：默认使用 `app.db`（工作目录下），是否接受？还是需要放在子目录如 `data/app.db`？

2. **旧数据处理**：
   - 方案 A：忽略旧数据，项目重启后用种子数据初始化（建议，因为是开发项目）。
   - 方案 B：提供迁移脚本，将 `users.json` + `departments.json` 自动导入 SQLite。

3. **验证码会话是否持久化**：当前方案将 `SESSION_STORE` 改为 SQLite 持久存储。原行为是进程重启后全部丢失。是否需要添加过期清理逻辑？还是保持当前无 `created_at` 无 TTL？

4. **查询历史上限**：当前是内存列表上限 10 条。迁移到 SQLite 后，是保持 `LIMIT 10`（查最新 10 条），还是同时增加总数上限（如最多保留 100 条再淘汰旧记录）？

5. **上传数据过期**：当前上传的 `data_*.json` 散落在工作目录。迁移到 SQLite 后支持级联删除（`ON DELETE CASCADE`）。是否需要增加文件级删除接口？当前无此功能。

6. **密码明文存储**：当前项目密码明文存放在 JSON 文件中（如 `"password": "123456"`），此问题在迁移前就存在，不属于本次迁移范围。但需要确认是否在本次迁移中顺便改为哈希存储（`bcrypt`）？这会增加 `requirements.txt` 依赖。
