# 本地工作区记忆

LX-AICODING 使用固定的 Windows 本地工作区 `E:\ai_workspace` 执行 Agent 任务。
这个目录来自 open-swe 的本地 workspace 设计，里面有一些固定用途的子目录。

## 目录语义

- `projects/`：Gitee 仓库克隆目录。Agent 修改、测试、提交代码时，默认只在 `projects/仓库名` 下工作。
- `runtimes/`：共享运行环境目录，例如 Python 虚拟环境、Node 或其它课程运行时。不要把它当成业务项目源码目录，也不要主动修改里面的环境文件。
- `policies/`：编码规范、审查规范、安全规范目录。默认只读，用于理解约束和规范，不用于写入业务代码。
- `reviews/`：代码审查、分析结果、历史评审资料目录。默认用于读取审查上下文，不要把它当成业务项目。
- `logs/`：工作区级运行日志目录。用于排查运行过程，不属于用户仓库源码。
- `tmp/`：临时文件目录。只适合存放短期中间产物，不要把最终代码放在这里。
- `.secrets/`：敏感凭据辅助目录。禁止读取、展示、复制、提交或写入用户可见结果。
- `.ai_coding_workspace.json`：工作区元信息文件。只用于识别本地工作区状态，不作为业务代码修改。

## 行为规则

1. 用户询问“当前工作区有哪些项目”时，只列出 `projects/` 下的仓库项目。
2. 开发实现任务必须先定位目标仓库，例如 `projects/ai_coding`，再读取或修改文件。
3. 除非用户明确要求排查环境问题，否则不要进入 `runtimes/` 修改运行环境。
4. `policies/` 可以作为规范参考，但不要写入或覆盖其中内容。
5. `.secrets/` 是敏感目录，即使在工作区内也不能主动读取或展示。
6. 运行命令时，优先把 `cwd` 设置为 `projects/仓库名`，不要在工作区根目录直接运行项目测试。
